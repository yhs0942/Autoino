# 5단계: 배선 직접 고치기 · 핀 공유 · 모터 연결 · 실물 배치

## 목표

자동 배치·자동 배정 결과를 사람이 손으로 고칠 수 있게 하고, 실제 제작에 필요한 정보를 더한다.

## 브레드보드 전선 옮기기

- 전선 끝(구멍의 점)을 끌어 다른 구멍에 놓는다. 처음 옮길 때 그때의 모든 전선 구멍을
  `breadboardHoles`(끝점 키 → 구멍 ID, 예: `12c`, `top-4`)에 기록해, 손대지 않은 전선이 움직이지 않게 한다.
- 배치 엔진(`engine/breadboard.ts`)은 기록된 구멍을 먼저 꽂고, 그 줄을 그 넷의 것으로 본다.
  자동 배치는 그런 열을 피한다. 한 넷이 여러 줄에 걸치면 점퍼로 잇는다(레일이 있으면 레일로).
- `checkLeadMove` 가 놓을 수 없는 자리를 막는다: 이미 찬 구멍, 다른 넷이 꽂힌 줄(단락),
  직렬 저항의 부품 쪽 줄(저항을 건너뜀), 저항 핀을 레일에 꽂기, 점퍼 자리가 남지 않는 줄.
- 저항이 붙는 핀(LED 애노드, 사다리 버튼)을 옮기면 저항도 그 열로 따라간다.
- 부품 핀을 끌어 구멍에 놓으면(`connectToHole`) 그 줄의 전선 핀과 잇고(보드 핀 우선), 빈 줄이면 맞는 보드 핀을 고른다.
- 전선이 사라지면 그 끝점의 구멍 기록도 지운다. **자동 배치로 되돌리기**는 기록을 모두 지운다.

## 보드·부품 핀에서 전선 끝 옮기기

- 전선을 고르면 양 끝에 손잡이가 생긴다. 끌어서 다른 핀에 놓으면 `retargetWire` 가 같은 전선 ID 로 다시 잇는다.
  연결 규칙(같은 부품 핀끼리 금지 등)은 새 전선과 같고, 맞지 않는 핀이면 경고를 함께 알린다.
- 브레드보드를 거치는 보드 핀 전선 하나를 여러 연결이 나눠 쓰면 함께 옮기고, 꽂혀 있던 구멍은 새 핀이 이어받는다.

## 전선이 어느 핀에 물렸는지 보기

- 전선이 물린 부품 핀 칩의 오른쪽 위에 그 전선과 같은 색 점을 찍는다.
- 핀 칩·보드 핀·전선을 가리키면 그 전선을 부품 카드 위로 올려 칩까지 보여 주고, 반대쪽 끝 핀을 표시한다.
  카드 안 구간은 다른 칩 이름이 보이도록 얇은 점선으로 그린다. 칩 설명(마우스를 올리면 뜨는 글)에 연결 상대를 적는다.
- 전선을 고르면 같은 방식으로 카드 위에 보이고, 양 끝 손잡이와 삭제 단추도 카드 위에 둔다.

## 직각 배선

- 부품 칩의 전선은 반대쪽 끝을 향한 카드 가장자리(위·아래)로 나가고, 처음 꺾는 곳은 카드 밖이다.
  같은 가장자리로 나가는 전선은 칩의 가로 순서대로 출구를 8 px 이상 벌린다 (`routeWires`).
- 꼭 필요한 만큼만 꺾는다: 마주 보면 Z자 2번(세로줄이 같으면 곧게), 같은 쪽을 보면 ㄷ자 2번, 등지면 4번.

## 핀 공유

- 부품 신호 핀을 같은 종류의 다른 핀(같은 부품의 다른 핀 포함)에 놓으면 `shares`(그룹 ID, 멤버 끝점 키)가 생기고, 멤버 모두가 같은 보드 핀에 연결된다.
  같은 종류 신호가 이미 쓰는 보드 핀에 놓아도 묶이고, 속성 패널의 **핀 공유**에서 함께 쓸 핀을 고를 수도 있다.
- 묶을 수 있는 것 (`shareRole`): 출력(LED·부저·릴레이 입력)끼리, 버튼끼리, 그리고 같은 종류의 출력 신호끼리
  — 서보·연속 회전 서보·ESC 신호, NeoPixel DIN, TM1637 CLK, STEP, DIR, RC522 RST, 보드 TX(모듈 RXD), 초음파 TRIG,
  H 브리지의 EN(PWM)·IN·STBY·두 입력 PWM, ULN2003 코일 입력(같은 번호). 종류가 다르면 이유를 알리고 묶지 않는다.
  같은 채널의 IN1·IN2 는 늘 같은 값이 되어 모터가 돌 수 없으므로 막는다.
- 코드: 신호 핀이 하나뿐인 부품(LED·서보 등)과 STEP 을 함께 쓰는 스텝 드라이버는 그룹 첫 부품의 코드가 함께 움직인다
  (같은 핀에 Servo 객체를 둘 붙이거나 펄스를 두 번 내지 않게). 첫 드라이버의 코드가 따로 연결된 DIR 도 같은 방향으로 맞춘다.
  핀이 여럿인 부품(초음파·H 브리지 등)은 공유 핀을 같은 상수로 쓰며 각자 코드를 만든다.
- 아날로그 센서 출력끼리는 한 핀에 묶지 않고 **아날로그 멀티플렉서(CD74HC4067, `cd74hc4067`)** 를 넣는다 (`engine/mux.ts`).
  센서마다 채널(C0…)을 주고 SIG 를 아날로그 핀 하나에, 선택선은 쓰는 채널 수만큼(2개 → S0, 4개 → S0·S1 …) 보드 핀에, 나머지 선택선과 EN 은 GND 에 잇는다.
  모듈 데이터의 `mux` (`common`, `select`, `channels`) 로 정하며, GND 에 묶은 선택선은 검사·자동 배정에서 오류로 보지 않는다.
  코드는 `readMux1(채널)` 함수로 선택선을 바꾸고 첫 값을 버린 뒤 읽는다. 핀 배정표에는 `멀티플렉서 C0 (SIG → A0)` 처럼 보인다.
- 버튼 그룹이 AVR 의 아날로그 겸용 핀에 있고 4개 이하이면 저항 사다리로 본다.
  직렬 저항 0 Ω / 4.7 kΩ / 22 kΩ / 100 kΩ, 내부 풀업 20–50 kΩ 범위에서 겹치지 않는 analogRead 경계를 계산해 코드에 넣는다.
  ESP32 는 analogRead 가 내부 풀업을 끄므로 사다리로 쓰지 않는다(입력 공유).
- 검사: 그룹 멤버만 쓰는 핀은 `pin-shared`(정보), LED 전류 합이 핀 한계를 넘으면 `pin-shared-current`(경고).
  그룹 없이 한 핀에 두 신호면 여전히 `pin-conflict` 오류이며, 묶을 수 있는 조합이면 묶는 방법을 안내한다.
- 자동 배정은 그룹을 유지하고, 끊긴 멤버는 다른 멤버의 보드 핀에 다시 잇는다. TS·Python 엔진이 같은 규칙을 쓰고 공유 픽스처로 비교한다.

## 모터를 드라이버에 끌어 놓기

- 드라이버 채널마다 받을 수 있는 모터 종류(`accepts`)가 있고, 한 채널에 모터 하나. 종류가 맞지 않으면 맞는 드라이버를 알려 준다.
  채널이 다 차면 "최대 N개"를 알린다.
- 서보는 보드 PWM 핀에 바로 연결하거나 서보 드라이버(PCA9685, 16채널, I²C 0x40)에 연결한다. 서보 드라이버에 놓으면
  신호선은 빈 채널 출력에, 서보 전원은 드라이버 V+ 에, GND 는 드라이버 GND 에 잇고, 드라이버의 I²C·로직 전원을 보드에 배정한다.
  V+ 에 물린 서보 전류를 모아 외부 전원 수요(전압 범위는 서보 정격과 겹치는 범위)를 계산한다.
  코드는 Adafruit PWM Servo Driver Library 로 채널마다 펄스(500–2500 µs)를 보낸다.
- 외부 전원이 꼭 필요한 전원 핀(V+ 등)이 다른 부하에만 물리고 전원이 없으면 `supply-missing` 오류로 알린다.
- 연결하면 모터 단자를 채널 출력에 잇고, 그 채널의 제어 핀과 드라이버 로직 전원을 배정하고, 모터 카드를 드라이버 옆으로 옮긴다.
- 드라이버가 없는 모터 카드에는 **드라이버 필요** 표시와 맞는 드라이버 추가 단추가 있다.

## 동작 시뮬레이션

- **시뮬레이션**을 누르면 `engine/sim/runtime.ts` 가 생성 코드(codegen)의 부품별 예시 동작을 같은 주기로 돌린다:
  LED 0.5 s 깜박임, 릴레이·부저 1 s, 서보 20 ms 마다 2° 왕복, H 브리지 2 s 마다 정방향 → 정지 → 역방향 → 정지(속도 180/255),
  ULN2003 3 ms·STEP/DIR 2 ms 마다 한 스텝(200 스텝마다 방향 전환), NeoPixel 0.1 s 마다 한 칸, TM1637·OLED·LCD 시간 표시,
  센서 값 출력(버튼 20 ms, 디지털 입력 50 ms, 아날로그 0.5 s, 조이스틱·초음파·IMU 0.2 s, DHT 2 s) 등. 시리얼 모니터 출력 형식도 코드와 같다.
- 보드가 내보내는 핀 신호를 배선(레벨 시프터 경유 포함, 핀 공유·멀티플렉서 포함)을 따라 부품에 전달한다. 모터는 드라이버 진리표
  (EN·IN, 두 입력 PWM, STBY)와 드라이버 전원 전압 − 전압 강하로 회전수를 정한다 (`engine/sim/behavior.ts` 의 대표 무부하 회전수).
- 필요한 핀이 미연결이거나, 전원 핀에 전압이 없거나, 검사 오류가 있는 부품은 움직이지 않고 이유를 카드에 보여 준다.
  모터 과전압·드라이버 과전류처럼 실물은 돌아가는 오류는 움직이며 경고한다. 전원 용량 초과는 떨림·리셋 경고로 보인다.
- 버튼·조이스틱·엔코더·가변저항·조도·토양·가스·초음파 거리·온습도·PIR·라인·IMU 기울기·RFID 카드·블루투스 메시지는 카드에서 조작한다.
  보드에는 전원(ON)·L(D13, ESP32 는 GPIO2)·TX LED 가 보인다. 시뮬레이션 중에는 배선을 고칠 수 없다.

## 내 코드 실행 (코드 시뮬레이션)

- `engine/arduino/` 는 브라우저에서 도는 Arduino C++ 인터프리터다. 전처리(`#include`·`#define`·함수형 매크로·`#if defined`) →
  구문 분석(전역·함수·구조체·열거형·참조·포인터·배열·`String`·모든 제어문·연산자) → 클로저로 컴파일한다.
  기다리는 코드(`delay`, 반복문, 그런 함수를 부르는 함수)만 제너레이터로 만들어, 가상 시간으로 실행하다가 프레임마다 양보한다.
  AVR 은 `int` 16비트·`double` 32비트(넘침·부호 규칙 그대로), ESP32 는 32/64비트. `sprintf` 의 `%f` 는 AVR 에서 `?` 다.
- 라이브러리: Servo·ESP32Servo, Wire(주변장치 모드 포함), SPI(AVR 레지스터 SPCR·SPDR 과 `ISR(SPI_STC_vect)` 포함),
  LiquidCrystal_I2C, Adafruit_SSD1306(+GFX 도형·글자), Adafruit_NeoPixel(색 순서 반영), TM1637Display, DHT, NewPing, MFRC522,
  SoftwareSerial, Stepper, AccelStepper, Adafruit_PWMServoDriver, Adafruit_MPU6050, MPU6050(I2Cdev), EEPROM, FastLED(기본).
  Wi-Fi·내장 블루투스·사용자 class·템플릿·람다·new 는 지원하지 않는다고 알린다.
- `engine/sim/hardware.ts` 는 보드마다 `Host`(핀 상태, UART, I²C, SPI, 장치)를 만든다. 보드 핀을 읽으면 그 핀의 넷에 물린 신호원
  (버튼이 이은 GND·전원, 센서 출력, 엔코더 위상, 초음파 에코 구간, 다른 보드 출력, 내부 풀업)을 전압·내부 저항으로 합쳐 판단한다.
  아무것도 없으면 떠 있는 값이다. UART 는 USB 모니터·HC-05·다른 보드로 보율을 따져 전달하고, I²C 는 넷으로 같은 버스의 장치
  (MPU-6050·PCA9685 레지스터, LCD·OLED, 주변장치 보드)를 찾는다.
- `engine/sim/codeRuntime.ts` 는 이 핀 상태로 부품 모습을 만든다. LED 는 애노드·캐소드 양쪽과 PWM, 서보는 펄스 폭(움직이는 속도 포함),
  ESC 는 최소 스로틀 시동, 28BYJ-48 은 켜진 코일 방향을 회전자가 따라가는 방식(코일 순서가 틀리면 떨림, 너무 빠르면 탈조),
  STEP/DIR 은 펄스 수로 돈다.
- `shared/fixtures/sketches.json`(백엔드가 만든 예시 스케치)을 모두 실행해 오류가 없고, 예시 동작 시뮬레이션과 부품 모습이 같은지
  `engine/sim/sketches.test.ts` 가 검사한다. 코드 생성을 바꾸면 `UPDATE_FIXTURES=1 python -m pytest tests/test_sketch_fixtures.py` 로 다시 만든다.

## AI 프롬프트

- `engine/aiPrompt.ts` 의 `buildAiPrompt` 가 만들 동작, 보드 사양, 부품마다 핀과 코드 번호(D7 → 7, ESP32 GPIO21 → 21)·직렬 저항·핀 공유,
  부품별 코드 요령(버튼 INPUT_PULLUP, 28BYJ-48 의 IN1·IN3·IN2·IN4 순서, ESC 시동 등), 외부 전원, 보드 간 통신, 시뮬레이터 조건을 적는다.
- `extractSketches` 는 AI 답변에서 코드 블록만 꺼내 보드 이름 주석(`// 보드 2`)이나 블록 위 제목으로 보드를 정한다.

## 외부 전원

- 외부 전원이 필요한 부품 카드에 **⚡ 전원 필요** 표시. 눌러서 그 자리에서 예시를 골라 연결한다. 부품 속성에도 같은 단추가 있다.
- 라이브러리에서 외부 전원을 놓으면 아직 전원이 없는 부품(카드 위에 놓으면 그 부품)에 맞춰 전압·전류를 정하고 연결한다.
  + 는 그 부품의 전원 핀에만, − 는 그 부품 GND 와 보드 GND 에 연결한다(외부 전원이 필요한 11종 × 직결·브레드보드 경유로 검사).
- 전압이 같은 외부 전원은 **하나로 합치기**로 묶는다. 전류 용량은 두 전원을 더한 값 이상인 선택지로 맞춘다.
- 외부 전원 부품의 **전원 종류** 파라미터(`supply`)에 어떤 제품인지(`data/power-supplies.json` 의 ID, 직접 정했으면 `custom`)를 기록한다.
  전원 예시를 적용하거나 놓아서 자동 연결하면 고른 예시가 기록되고, 종류를 고르면 전압·전류가 그 제품의 대표값으로 맞춰진다.
  전압·전류를 따로 바꾸거나 전원을 합쳐 제품과 달라지면 직접 설정으로 바뀐다.
- [전원] 탭의 **사용 중인 외부 전원**에서 전원마다 종류(어댑터·배터리·USB)와 제품 이름, 출력 전압·최대 전류, 배터리 용량,
  지금 쓰는 전류와 예상 사용 시간, 연결 요령, 전기를 받는 부품을 보여 주고 종류를 바꿀 수 있다.
  직접 설정한 전원에는 같은 전압에 전류가 충분한 제품 예를 알려 준다. 카드에는 종류(예: 배터리 · 7.4 V · 5 A)가 보인다.

## 실물 배치 보기

- 보드·부품·브레드보드를 대표 실물 크기(mm, `sizeMm`)의 같은 비율(4 px/mm)로 그린다. 전선·글자는 그리지 않는다.
- 위치는 `layout`(인스턴스 ID 또는 `breadboard` → 좌표)에 배선도와 따로 저장한다. 처음에는 배선도 위치를 빌려 쓰고 겹치면 비켜 놓는다.
- 크기는 흔한 제품의 대표값이며 제품마다 다르다.

## 저장 형식

프로젝트 파일 버전은 2 그대로이고, 아래 필드를 값이 있을 때만 쓴다. 예전 파일은 그대로 열린다.

| 필드 | 내용 |
|---|---|
| `breadboardHoles` | 끝점 키 → 구멍 ID |
| `shares` | `{ id, members[] }` 목록 |
| `layout` | 인스턴스 ID 또는 `breadboard` → `{ x, y }` |
| `sketches` | 보드 인스턴스 ID → 사용자가 넣은 스케치 (실행 취소 기록에는 넣지 않는다) |

서버 저장(`projects/`)과 자동 배정 API 도 이 필드를 보존한다.
